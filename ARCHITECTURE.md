# ARCHITECTURE.md

## System Overview

AuditAI is a client-first web application that helps startups analyze and optimize their AI tool spending across subscriptions and API usage.

Users input their AI stack, including tools, plans, monthly spend, seats per tool, total team size, and primary use case. This structured input is processed through a deterministic audit engine that evaluates pricing efficiency, seat allocation, and usage fit.

The output is a structured financial audit that highlights:
- unnecessary or overlapping tools
- over-provisioned plans relative to usage
- cheaper plan alternatives within the same vendor
- lower-cost alternative tools with similar capabilities

The system is designed to produce **accessible, financially knowledgeable recommendations** that a startup founder or engineering manager can trust.

## Data Flow

### 1. Input Layer
Users provide:
- tool name (e.g., ChatGPT, Cursor)
- plan tier
- monthly spend
- number of seats
- team size
- primary use case (coding, writing, research, mixed)

This data is stored in React state (`toolsList`) and optionally persisted in `localStorage` to prevent data loss.

---

### 2. Audit Engine (Core Logic Layer)

The audit engine is a deterministic rule-based system responsible for generating recommendations.

For each tool entry, it evaluates:

- Plan suitability:
  - Is the user overpaying for unused capacity?
  - Is the plan underpowered for usage?

- Intra-vendor optimization:
  - Cheaper plan available within same provider

- Cross-vendor substitution:
  - Alternative tools with similar capability at lower cost

- API inefficiencies:
  - Direct API usage vs bundled pricing comparisons

- Consolidation opportunities:
  - Multiple overlapping tools performing similar functions

Each tool produces:
- current cost
- optimized cost
- savings
- recommendation type
- explanation (1–2 lines, human-readable)

This layer is fully deterministic and does NOT rely on AI.

---

### 3. Pricing Data Layer

All pricing data is stored locally in:

- `/data/tools.ts`
- `/lib/pricing-data.ts`

Rules:
- Every price is sourced from official vendor pricing pages
- All pricing entries are documented in `PRICING_DATA.md`
- Data is versioned with timestamps
- No runtime external API calls for pricing

This ensures audit consistency and traceability.

---

### 4. Recommendation Layer

Each recommendation is categorized as:

- downgrade plan
- upgrade plan
- switch tool
- consolidate tools
- already optimized

Each recommendation includes a short reasoning statement that is:
- deterministic
- based on pricing + usage rules
- not generated by LLM

---

### 5. AI Summary Layer (Optional)

An LLM (Anthropic/OpenAI) is used only for generating a natural language summary of the audit.

Constraints:
- never used for financial calculations
- must gracefully fallback to templated summary if API fails
- prompt stored in `PROMPTS.md`

This ensures that core logic remains deterministic while adding optional personalization.

---

### 6. Output Layer (UI)

The results page includes:

1. Per-tool breakdown
   - current spend
   - optimized spend
   - savings
   - recommendation

2. Total summary
   - total monthly savings
   - total annual savings

3. Insight section
   - key inefficiencies
   - consolidation opportunities

4. CTA section
   - leads captured for high-savings users
   - neutral messaging for optimized users

The UI is designed for shareability and screenshot readability.

---

### 7. Lead Capture & Storage

After audit results, users can optionally provide:
- email
- company name
- role
- team size

Data is stored in:
- Supabase 

Security measures:
- rate limiting
- honeypot field for bot prevention
- optional captcha integration

Transactional emails are sent using:
- Resend / Postmark / AWS SES

---

### 8. Shareable Audit URLs

Each audit generates a unique public URL:

/audit/[id]

Rules:
- No personal data is exposed
- Only anonymized tool + savings data is shown
- Open Graph metadata enabled for social sharing
- Designed for viral distribution (Twitter, LinkedIn, Hacker News)

## Stack Justification

### Framework: Next.js (React)

Next.js is used due to:
- hybrid rendering (SSR + CSR)
- built-in routing system
- API route support for backend logic
- SEO optimization for landing pages
- easy deployment via Vercel

---

### TypeScript

TypeScript is used to:
- enforce structure on audit data
- prevent calculation errors
- improve maintainability of audit engine logic
- ensure safe transformations of financial data

---

### UI System

- Tailwind CSS for utility-first styling
- custom component system (no prebuilt dashboard templates)
- brutalist editorial design approach

This ensures:
- full design control
- lightweight bundle size
- high Lighthouse performance scores

---

### Performance Strategy

To meet Lighthouse requirements (85+ performance, 90+ accessibility):

- minimal client-side state
- lazy rendering of results sections
- separation of UI and computation layers
- avoidance of heavy UI libraries
- optimized re-render patterns in React

---

### Security & Environment Handling

No secrets are stored in the repository.

All external integrations use environment variables:

- process.env.ANTHROPIC_API_KEY
- process.env.RESEND_API_KEY
- process.env.DATABASE_URL

This ensures safe deployment and prevents credential leakage.

---

## Scaling Considerations (10k audits/day)

If scaled, the system would evolve as follows:

- audit engine moved to serverless functions
- pricing data cached at edge
- LLM summaries processed asynchronously via queue
- Redis caching for repeated audit patterns
- database writes batched for efficiency

---

## Design Philosophy

- Deterministic logic over probabilistic AI
- Explainable financial recommendations over “black box” insights
- Transparency over complexity
- Every output must be traceable to pricing data
- AI is used only for communication, not computation

---

## Key Tradeoff

A strict separation is maintained between:

- Audit Engine (deterministic financial logic)
- AI Layer (language + summarization only)

This ensures the system remains auditable, predictable, and trustworthy.

---

## Summary

AuditAI is designed as a trust-first financial optimization tool for AI spend. The architecture prioritizes correctness, explainability, and scalability while keeping AI as an optional enhancement layer rather than the core decision engine.
